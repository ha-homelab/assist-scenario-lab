## التثبيت والحدود

ثبّت من نسخة المستودع باستخدام `python3 -m pip install .` داخل بيئة افتراضية. يُدعم Python 3.11+. لا توجد اعتماديات تشغيل غير Python. يعرض `assist-lab --help --lang en` الأوامر؛ وتعمل أيضاً `ru` و`de` و`es`. نقطة الدخول عبر الوحدة هي `python3 -m assist_scenario_lab`.

يتطلب تحميل الملفات علمَي نظام التشغيل `O_NOFOLLOW` و`O_NONBLOCK`، المتاحين على Linux وmacOS. عند غياب أيّ منهما تعيد CLI رمز الخروج 2 مع `unsupported_platform` قبل فتح الإدخال. لا تحتاج واجهات Python للتقييم والاستيراد في الذاكرة إلى هذين العَلَمين.

هذا مقيّم يعمل دون اتصال، وليس برنامجاً ثابتاً لجهاز تابع أو كاشفاً صوتياً أو جامعاً مباشراً للبيانات أو تكاملاً مع HA أو اختبار أداء كاملاً. أجرِ اختبارات قبول المستخدم الفعلية للمنتج بأدوات البرنامج الثابت المناسبة. لا تقدّم الأدلة الناتجة محدودة الحجم لهذه الأداة إلا بعد مراجعة الخصوصية.

## الإدخال القياسي

ابدأ من `examples/synthetic-pass.json`. يتطلب الجذر `schema: assist-scenario-lab/v1`، والقيمة المنطقية `synthetic`، وكائن `requirements`، وما بين 1 و500 من `sessions`. تُرفض الحقول غير المعروفة. تحتوي الجلسة على `id` فريد، إضافة إلى `platform` و`scenario` و`clock` و`events` و`checks`. تتكون المعرّفات من 1–64 حرف ASCII أو رقم أو شرطة سفلية أو شرطة، وتبدأ بحرف أو رقم. استخدم أسماء مستعارة لا أسماء غرف أو عناوين أو معرّفات أجهزة.

تكون `clock` إما `relative_monotonic` أو `utc_derived`. تحتوي الأحداث على `stage` و`at_ms` و`origin`. الأزمنة منتهية وغير سالبة، لا تتجاوز 12 ساعة، ومرتبة ترتيباً غير تنازلي. أول حدث هو `request` عند الصفر. تظهر كل مرحلة مرة واحدة. المراحل المدعومة: `request` و`wake_detected` و`stt_end` و`intent_end` و`tts_ready` و`protocol_end` و`playback_started` و`playback_finished` و`audible_start` و`error`. قد تعمل المسارات المختلفة بالتدفق؛ لذلك لا يُفرض عمداً ترتيب ثابت بين TTS والتشغيل بخلاف التسلسل الزمني للطوابع.

المصادر هي `pipeline` و`satellite` و`operator` و`acoustic`. لا يمكن أن يكون مصدر `audible_start` إلا `operator` أو `acoustic`. يجب أن تقدم كل جلسة الفحوص الثلاثة: `intent_correct` و`action_observed` و`audible`. لكل منها `result` (`pass` أو `fail` أو `unknown`) و`method`. تتطلب النتيجة المجهولة `none`. الطرق الأخرى الصالحة هي `operator`/`intent_assertion` للنية، و`operator`/`ha_state` للإجراء، و`operator`/`acoustic` للسماع. يتطلب الطابع الزمني للصوت المسموع نجاح فحص السماع. تتحقق الأداة من الاتساق، لا من الحقيقة.

يمكن للمتطلبات تفعيل أي فحص من الثلاثة، واختيارياً `max_audible_ms`. الفحوص المحذوفة أو ذات القيمة false ليست إلزامية: يمكن لسياسة تقتصر على API أن تنجح دون دليل مادي، ويجب وسمها بذلك. تتطلب الأمثلة المرفقة جميع الفحوص. خطأ المسار يؤدي دائماً إلى الفشل. غياب `protocol_end` يعني عدم الاكتمال. يتقدم فشل متطلب إلزامي على الملاحظات المجهولة. التأخير فوق العتبة فشل؛ وغياب التأخير المطلوب عدم اكتمال.

## استيراد تشغيل HA

يستقبل المهايئ **مصفوفة واحدة من كائنات الأحداث**، لا سجل WebSocket كاملاً ولا ملف ZIP تشخيصياً. استخرج محتوى كل حدث محلياً. تحتوي الكائنات على `type` و`timestamp` و`data` بالضبط؛ وقد تكون البيانات كائناً أو null. يجب أن تكون الطوابع الزمنية ISO 8601 مع منطقة زمنية. ابدأ بـ`run-start`، وحافظ على الترتيب الزمني، ولا تخلط تشغيلات مختلفة. تُرفض المراحل المكررة بعد التحويل.

يعيد الأمر الثاني 3 عمداً. تتحول `run-end` إلى `protocol_end`، لا إلى نجاح مادي. وتتحول `tts-end` إلى `tts_ready`، لا إلى صوت مسموع. تُحذف جميع `data`، بما فيها النصوص المفرّغة ونص الإدخال والأخطاء وعناوين URL/رموز TTS وبيانات المسار الوصفية. تُعرف أحداث البداية والتقدم وVAD لكنها لا تُحفظ. تستخدم الأزمنة المحوّلة `utc_derived`: طرح أوقات الساعة ليس قياس تأخير رتيباً وقد يتأثر بتعديل الساعة. تبقى الفحوص المادية/الدلالية الثلاثة مجهولة.

## التقارير والمقارنة

يختار `--format text|json|html|junit` التقرير. تكتب إعادة توجيه الصدفة النتيجة إلى مسار محلي تختاره. لا تكتب CLI نفسها فوق الإدخال أبداً. رموز الخروج: 0 لنجاح المتطلبات المسجّلة؛ 1 للفشل؛ 2 لإدخال أو وسيطات غير صالحة؛ 3 لعدم الاكتمال. يمثّل JUnit الجلسات غير المكتملة كمتخطّاة؛ لكن يجب على CI احترام الرمز 3.

تستخدم مجموعات JSON المنصة + السيناريو + الساعة + طريقة توقيت السماع. لا تعتبر الساعات المختلفة أو الملاحظات البشرية والصوتية قياسات قابلة للاستبدال. يستخدم p50/p95 أقرب رتبة. تكون p95 بقيمة null لأقل من 20 عينة؛ فالعدد 20 عتبة عرض، لا دليل ثقة إحصائية. تبقى الجلسات الفاشلة التي لوحظ فيها صوت ضمن مجتمع عينات التأخير، ويظل عدد فشلها ظاهراً. لا تنتقِ المحاولات الناجحة فقط. لا يُصدَّر صوت خام أو تفريغ نصي. قد تكشف المعرّفات معلومات رغم ذلك، فراجعها.

يسرد HTML كل الجلسات ويرسم أول 50 ملاحظة مسموعة بمقياس مشترك. اقرأ منصة وطريقة كل صف؛ النظرة العامة ليست تصنيفاً إحصائياً. توجد `evidence_verified: false` دائماً. تعني `synthetic: false` أن المؤلف لم يوسم التشغيل بأنه اصطناعي، لا أن العتاد خضع لتحقق مستقل.

## جمع أدلة مفيدة

حدّد النية المتوقعة والهدف قبل المحاولة. استخدم تعريفاً ثابتاً لحدث البدء: طلب المسار ليس بالضرورة بداية العبارة المنطوقة. احتفظ بسجل خارجي يتضمن إصدارات البرمجيات واللغة وظروف الشبكة وموضع الميكروفون والسماعة وطريقة المراقبة وعدد المحاولات. استخدم قياساً صوتياً مناسباً لتوقيت السماع بدقة؛ لا تستبدله بأول قطعة بيانات شبكية. سجّل الفشل وانتهاء المهلة والأدلة المفقودة. لا تنفذ هذه الحزمة مزامنة صوتية أو إدارة للموافقة.

## استكشاف الأخطاء وإصلاحها

- `object_fields`: قارن المفاتيح ببيانات الاختبار القياسية؛ لا يُقبل تفريغ تشخيصي كامل.
- `ha_timestamp` / `time_order`: صدّر تشغيلاً واحداً، وأدرج المناطق الزمنية، وافحص تصحيحات الساعة. لا تعد ترتيب الأحداث لاختلاق تأخير.
- `stage`: مرحلة مجهولة أو مكررة؛ افحص إن كان قد جُمِع تشغيلان.
- `audible_origin` / `conflicting_audible`: بيانات التشغيل الوصفية لا تحل محل سماع الصوت.
- رمز 3 بعد نجاح API: متوقع حتى تسجيل الملاحظات المطلوبة.
- `unsupported_platform`: يفتقد النظام `O_NOFOLLOW` أو `O_NONBLOCK`؛ استخدم بيئة توفرهما معاً، مثل Linux أو macOS. يُرفض الإدخال قبل فتحه بدلاً من إضعاف فحوص الروابط الرمزية أو FIFO.
- `file_size_type`: ملفات JSON UTF-8 العادية فقط، بحد أقصى 2 MiB. تُرفض الأدلة وFIFO والروابط الرمزية في آخر مكوّن للمسار. الروابط في الأدلة الأب ليست حدّاً لصندوق العزل.
- `number`: لا تقبل طوابع زمنية سالبة أو غير منتهية أو منطقية أو تتجاوز 12 ساعة.

تطبع الأخطاء ملخصاً مترجماً ورمزاً ثابتاً، لا محتويات المصدر ولا المسارات المحلية. الأمثلة العامة اصطناعية بالكامل. احتفظ بالتصديرات خارج نسخة المستودع هذه، ويفضل في دليل مؤقت خاص.

## البنية والترجمات والمصادر

![التدفق دون اتصال](../../assets/architecture.svg)

يتولى `core.py` التحقق والاستيراد والتقييم الخالص؛ ويعرض `cli.py` الصيغ؛ وتحتوي `locales/*.json` على أربعة كتالوجات. تتطلب الاختبارات تطابق مفاتيح الكتالوجات. لا تُترجم مفاتيح الآلة أو رموز التشخيص. تغطي الأدلة الكاملة لغات توثيق ha-homelab الأربع والعشرين؛ وتبقى CLI وREADME بالإنجليزية والروسية والألمانية والإسبانية. ساهم بترجمات مرجعية إضافية مع اختبارات تكافؤ وأمثلة مراجعة.

رُوجع تحويل البروتوكول مقابل [توثيق Home Assistant Assist](https://developers.home-assistant.io/docs/voice/pipelines/) و[نماذج أحداث HA 2026.10.0](https://github.com/home-assistant/core/blob/2026.10.0/homeassistant/components/assist_pipeline/models.py). دورة حياة الجهاز التابع موثقة في [دليل الكيان الرسمي](https://developers.home-assistant.io/docs/core/entity/assist-satellite/). لا تعد هذه الواجهات المصدرية بتحقق صوتي؛ وفصله هنا قرار تصميمي.
