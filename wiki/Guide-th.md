## การติดตั้งและขอบเขต

ติดตั้งจากสำเนารีโพซิทอรีด้วย `python3 -m pip install .` ในสภาพแวดล้อมเสมือน รองรับ Python 3.11+ ไม่มีการพึ่งพาขณะรันนอกเหนือจาก Python คำสั่ง `assist-lab --help --lang en` แสดงรายการคำสั่ง โดย `ru`, `de` และ `es` ก็ใช้ได้ จุดเริ่มต้นแบบโมดูลคือ `python3 -m assist_scenario_lab`

การโหลดไฟล์ต้องใช้แฟล็กของระบบปฏิบัติการ `O_NOFOLLOW` และ `O_NONBLOCK` ซึ่งมีใน Linux และ macOS หากขาดตัวใดตัวหนึ่ง CLI จะคืนรหัสออก 2 พร้อม `unsupported_platform` ก่อนเปิดอินพุต API Python สำหรับประเมินและนำเข้าข้อมูลในหน่วยความจำไม่ต้องใช้แฟล็กเหล่านี้

นี่คือเครื่องมือประเมินแบบออฟไลน์ ไม่ใช่เฟิร์มแวร์อุปกรณ์ดาวเทียม ตัวตรวจจับเสียง ตัวเก็บข้อมูลสด อินทิเกรชัน HA หรือเบนช์มาร์กเต็มรูปแบบ ให้ทดสอบการยอมรับผลิตภัณฑ์โดยผู้ใช้จริงด้วยเครื่องมือเฟิร์มแวร์ที่เหมาะสม ส่งหลักฐานที่ได้ในขอบเขตจำกัดให้เครื่องมือนี้หลังตรวจสอบความเป็นส่วนตัวแล้วเท่านั้น

## อินพุตมาตรฐาน

เริ่มจาก `examples/synthetic-pass.json` รากต้องมี `schema: assist-scenario-lab/v1`, บูลีน `synthetic`, ออบเจ็กต์ `requirements` และ `sessions` จำนวน 1–500 รายการ ฟิลด์ที่ไม่รู้จักจะถูกปฏิเสธ เซสชันมี `id` ที่ไม่ซ้ำ พร้อม `platform`, `scenario`, `clock`, `events` และ `checks` ID มีอักษร ASCII ตัวเลข ขีดล่างหรือขีดกลาง 1–64 ตัว และเริ่มด้วยอักษรหรือตัวเลข ใช้นามแฝงแทนชื่อห้อง ที่อยู่ หรือรหัสระบุอุปกรณ์

`clock` เป็น `relative_monotonic` หรือ `utc_derived` เหตุการณ์มี `stage`, `at_ms`, `origin` เวลาต้องเป็นจำนวนจำกัด ไม่ติดลบ ไม่เกิน 12 ชั่วโมง และเรียงแบบไม่ลดลง เหตุการณ์แรกคือ `request` ที่ศูนย์ แต่ละช่วงเกิดได้ครั้งเดียว ช่วงที่รองรับ: `request`, `wake_detected`, `stt_end`, `intent_end`, `tts_ready`, `protocol_end`, `playback_started`, `playback_finished`, `audible_start`, `error` ไปป์ไลน์ต่างกันอาจใช้สตรีมมิง จึงตั้งใจไม่กำหนดลำดับตายตัวระหว่าง TTS กับการเล่นนอกเหนือจากลำดับเวลาประทับ

ต้นทางคือ `pipeline`, `satellite`, `operator` และ `acoustic` เฉพาะ `operator` หรือ `acoustic` เท่านั้นที่เป็นต้นทางของ `audible_start` ได้ ทุกเซสชันต้องส่งการตรวจทั้งสาม: `intent_correct`, `action_observed`, `audible` แต่ละรายการมี `result` (`pass`, `fail`, `unknown`) และ `method` ผลไม่ทราบต้องใช้ `none` วิธีอื่นที่ใช้ได้คือ `operator`/`intent_assertion` สำหรับเจตนา, `operator`/`ha_state` สำหรับการกระทำ และ `operator`/`acoustic` สำหรับการได้ยิน เวลาประทับเสียงที่ได้ยินต้องมีผลตรวจการได้ยินผ่าน เครื่องมือตรวจความสอดคล้อง ไม่ได้พิสูจน์ความจริง

ข้อกำหนดอาจเปิดการตรวจใดก็ได้ในสามรายการ และเลือกใช้ `max_audible_ms` การตรวจที่ละไว้หรือตั้ง false ไม่ใช่ข้อบังคับ นโยบายเฉพาะ API อาจผ่านโดยไม่มีหลักฐานทางกายภาพและต้องระบุเช่นนั้น ตัวอย่างที่ให้มากำหนดให้ตรวจครบทั้งหมด ข้อผิดพลาดไปป์ไลน์ทำให้ล้มเหลวเสมอ การไม่มี `protocol_end` คือไม่ครบถ้วน ความล้มเหลวของข้อบังคับมีความสำคัญเหนือการสังเกตที่ไม่ทราบ ความหน่วงเกินเกณฑ์ทำให้ล้มเหลว ส่วนการไม่มีค่าความหน่วงที่จำเป็นคือไม่ครบถ้วน

## การนำเข้าการรัน HA

อะแดปเตอร์รับ **อาร์เรย์ของออบเจ็กต์เหตุการณ์** หนึ่งชุด ไม่ใช่บันทึก WebSocket เต็มหรือ ZIP วินิจฉัย ให้แยกเนื้อหาของแต่ละเหตุการณ์ในเครื่อง ออบเจ็กต์มีเฉพาะ `type`, `timestamp`, `data` โดยข้อมูลเป็นออบเจ็กต์หรือ null ได้ เวลาประทับต้องเป็น ISO 8601 ที่มีเขตเวลา เริ่มด้วย `run-start` รักษาลำดับเวลาและอย่าผสมหลายการรัน ช่วงที่แมปแล้วซ้ำจะถูกปฏิเสธ

```sh
assist-lab import-ha examples/ha-events.synthetic.json --session demo --platform demo --synthetic > /tmp/imported.json
assist-lab evaluate /tmp/imported.json --format json
```

คำสั่งที่สองตั้งใจคืน 3 โดย `run-end` แมปเป็น `protocol_end` ไม่ใช่ความสำเร็จทางกายภาพ และ `tts-end` แมปเป็น `tts_ready` ไม่ใช่เสียงที่ได้ยิน `data` ทั้งหมดถูกทิ้ง รวมถึงข้อความถอดเสียง ข้อความอินพุต ข้อผิดพลาด URL/โทเคน TTS และเมทาดาทาไปป์ไลน์ เหตุการณ์เริ่มต้น ความคืบหน้า และ VAD ถูกตรวจรู้แต่ไม่เก็บไว้ เวลาที่แปลงใช้ `utc_derived` การลบเวลาตามนาฬิกาไม่ใช่การวัดความหน่วงแบบเพิ่มทางเดียวและอาจได้รับผลจากการปรับนาฬิกา การตรวจทางกายภาพ/ความหมายทั้งสามยังคงเป็นไม่ทราบ

## รายงานและการเปรียบเทียบ

`--format text|json|html|junit` เลือกรายงาน การเปลี่ยนทิศทางเชลล์เขียนผลลงพาธในเครื่องที่เลือก CLI ไม่เขียนทับอินพุตเองเด็ดขาด รหัสออก: 0 ข้อกำหนดที่บันทึกผ่าน; 1 ล้มเหลว; 2 อินพุต/อาร์กิวเมนต์ไม่ถูกต้อง; 3 ไม่ครบถ้วน JUnit แสดงเซสชันไม่ครบถ้วนเป็นข้าม แต่ CI ยังต้องเคารพรหัสออก 3

กลุ่ม JSON ใช้แพลตฟอร์ม + สถานการณ์ + นาฬิกา + วิธีจับเวลาที่ได้ยิน อย่าเปรียบนาฬิกาต่างกัน หรือการสังเกตโดยคนกับการวัดเสียง ว่าเป็นการวัดที่ใช้แทนกันได้ p50/p95 ใช้วิธีอันดับใกล้ที่สุด p95 เป็น null เมื่อมีน้อยกว่า 20 ตัวอย่าง ค่า 20 เป็นเกณฑ์รายงาน ไม่ใช่หลักฐานความเชื่อมั่นทางสถิติ เซสชันล้มเหลวที่สังเกตเสียงได้ยังอยู่ในกลุ่มตัวอย่างความหน่วงและจำนวนความล้มเหลวยังปรากฏ อย่าเลือกเฉพาะครั้งที่ผ่าน ไม่มีการส่งออกเสียงดิบหรือข้อความถอดเสียง ID ยังอาจเปิดเผยข้อมูล จึงต้องตรวจทาน

HTML แสดงทุกเซสชันและวาดการสังเกตเสียง 50 รายการแรกบนสเกลร่วม อ่านแพลตฟอร์มและวิธีของแต่ละแถว ภาพรวมไม่ใช่อันดับทางสถิติ มี `evidence_verified: false` เสมอ `synthetic: false` หมายถึงผู้เขียนไม่ได้ทำเครื่องหมายการรันว่าเป็นข้อมูลสังเคราะห์ ไม่ได้หมายความว่าฮาร์ดแวร์ได้รับการตรวจสอบโดยอิสระ

## การเก็บหลักฐานที่มีความหมาย

กำหนดเจตนาที่คาดหวังและเป้าหมายก่อนทดลอง ระบุเหตุการณ์เริ่มต้นอย่างสม่ำเสมอ คำขอไปป์ไลน์ไม่จำเป็นต้องเป็นจุดเริ่มต้นของวลีที่พูด เก็บบันทึกการทดลองภายนอกที่มีเวอร์ชันซอฟต์แวร์ ภาษา สภาพเครือข่าย ตำแหน่งไมโครโฟนและลำโพง วิธีสังเกต และจำนวนครั้ง ใช้การวัดเสียงที่เหมาะสมเพื่อจับเวลาที่ได้ยินอย่างแม่นยำ อย่าแทนด้วยชิ้นข้อมูลเครือข่ายแรก บันทึกความล้มเหลว หมดเวลา และหลักฐานที่ขาด แพ็กเกจนี้ไม่ทำการซิงโครไนซ์เสียงหรือจัดการความยินยอม

## การแก้ปัญหา

- `object_fields`: เทียบคีย์กับ fixture มาตรฐาน ไม่รับข้อมูลวินิจฉัยทั้งชุด
- `ha_timestamp` / `time_order`: ส่งออกการรันเดียว ใส่เขตเวลา และตรวจการปรับนาฬิกา อย่าสลับลำดับเหตุการณ์เพื่อสร้างค่าความหน่วง
- `stage`: ช่วงไม่รู้จักหรือซ้ำ ตรวจว่ามีการต่อสองการรันเข้าด้วยกันหรือไม่
- `audible_origin` / `conflicting_audible`: เมทาดาทาการเล่นใช้แทนการได้ยินเสียงไม่ได้
- รหัสออก 3 หลัง API สำเร็จ: เป็นผลที่คาดไว้จนกว่าจะบันทึกการสังเกตที่จำเป็น
- `unsupported_platform`: ระบบปฏิบัติการขาด `O_NOFOLLOW` หรือ `O_NONBLOCK` ให้ใช้สภาพแวดล้อมที่มีทั้งคู่ เช่น Linux หรือ macOS อินพุตถูกปฏิเสธก่อนเปิด แทนการลดความเข้มงวดของการตรวจลิงก์สัญลักษณ์หรือ FIFO
- `file_size_type`: รับเฉพาะไฟล์ JSON UTF-8 ปกติ สูงสุด 2 MiB ปฏิเสธไดเรกทอรี FIFO และลิงก์สัญลักษณ์ที่ส่วนสุดท้ายของพาธ ลิงก์ในไดเรกทอรีแม่ไม่ใช่ขอบเขตแซนด์บ็อกซ์
- `number`: ไม่รับเวลาประทับติดลบ ไม่เป็นจำนวนจำกัด เป็นบูลีน หรือเกิน 12 ชั่วโมง

ข้อผิดพลาดพิมพ์สรุปที่แปลแล้วกับรหัสคงที่ ไม่พิมพ์เนื้อหาต้นฉบับหรือพาธในเครื่อง ตัวอย่างสาธารณะเป็นข้อมูลสังเคราะห์ทั้งหมด เก็บไฟล์ส่งออกนอกสำเนารีโพซิทอรีนี้ โดยควรอยู่ในไดเรกทอรีชั่วคราวส่วนตัว

## สถาปัตยกรรม คำแปล และแหล่งข้อมูล

![กระบวนการออฟไลน์](https://raw.githubusercontent.com/ha-homelab/assist-scenario-lab/main/assets/architecture.svg)

`core.py` จัดการตรวจสอบ นำเข้า และประเมินแบบบริสุทธิ์; `cli.py` สร้างรูปแบบรายงาน; `locales/*.json` มีแค็ตตาล็อกสี่ชุด การทดสอบกำหนดให้คีย์ในแค็ตตาล็อกตรงกัน คีย์สำหรับเครื่องและรหัสวินิจฉัยไม่ถูกแปล คู่มือฉบับเต็มครอบคลุมภาษาเอกสาร ha-homelab ทั้ง 24 ภาษา ส่วน CLI และ README ยังเป็นอังกฤษ รัสเซีย เยอรมัน และสเปน ร่วมเพิ่มคำแปลอ้างอิงพร้อมการตรวจความตรงกันและตัวอย่างที่ตรวจทานแล้ว

การแมปโปรโตคอลตรวจเทียบกับ[เอกสาร Home Assistant Assist](https://developers.home-assistant.io/docs/voice/pipelines/) และ[โมเดลเหตุการณ์ HA 2026.10.0](https://github.com/home-assistant/core/blob/2026.10.0/homeassistant/components/assist_pipeline/models.py) วงจรชีวิตอุปกรณ์ดาวเทียมอยู่ใน[คู่มือเอนทิตีอย่างเป็นทางการ](https://developers.home-assistant.io/docs/core/entity/assist-satellite/) API ต้นทางเหล่านี้ไม่สัญญาการตรวจสอบเสียง การแยกส่วนนี้เป็นการตัดสินใจออกแบบของโครงการ
